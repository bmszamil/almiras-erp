## Compliance check: invoicing slice 1 against ZATCA/VAT and Sharia (read-only)

I edited no files. I could not reach the web, so every source below is a local copy downloaded on 2026-10-16 into `/tmp/claude-0/-home-user-almiras-erp/ea5f57b4-d147-5a57-9a1e-1750b3cc3f70/scratchpad/zatca-docs/`. Abbreviations: XML = XML Implementation Standard v1.2 (page shown as "NN/72"), DD = `data-dictionary-Data_dictionary.csv` (v1.2), TIR = Tax Invoicing and Records Guideline v3 (May 2026).

**What I found:**
- **Code lists:** the VATEX code set is complete and every code is correct. The wording differs from ZATCA's in two entries (VATEX-SA-34-5 and VATEX-SA-OOS), and four more differ only in capital letters. All five Arabic credit/debit note reasons are reworded rather than copied from the DD.
- **Blocking gaps:**
  - an entity with no VAT number can issue Z/E/O-only invoices;
  - the issue date can be in the future or backdated;
  - an export invoice to a VAT-registered buyer ends up with no buyer ID at all;
  - the SAR VAT rate is not forced to come from SAMA or from the tax due date;
  - VATEX-SA-OOS has nowhere to store its free-text reason.
- **Sharia:** no gaps in the code.
