## Summary

I checked the [CC-verify] items in both specs against the ZATCA documents downloaded on 2026-10-16, using only the local copies. I edited no repo file.

- **Most items match.** Several need precise wording, and a few are wrong:
  - **Subtype positions:** the flags are positions **3 to 7**. invoicing.md is right and zatca.md ("4–7") is wrong.
  - **Initial PIH:** the seed is base64 of the *hex text* of SHA-256("0"). Normal invoice hashes are base64 of the *raw 32-byte* digest.
  - **R-27 (submission order):** ZATCA does not require submission in ICV order.
  - **R48 (SAR 1,000 rule):** the rule covers more buyers than the spec says.
  - **Missing rules:** there are no rules yet for the clearance-disabled HTTP 303 path, the always-present SAR tax total, or a movable-capital-asset retention class.
- **Not available or not covered:** the Input Tax Deduction guideline, the RCM circular and the PDPL sources were not downloaded, so R29, R30 and R49–R53 are Still unclear / Unclear. The Data Dictionary "Stamp example" CSV is empty. No document gives a line-vs-header VAT tolerance, the compliance/PCSID endpoint paths, or any "simulation" environment.
- **Version check:** `specs-page.html` lists only the 20230519 Data Dictionary and XML Standard. No newer XML Standard or Data Dictionary is on that page.

## Positions 4–7 vs 3–7: resolved
BR-KSA-06 (XML v1.2 p.48) and DD KSA-2 define the subtype as `NNPNESB`. Positions 1–2 hold the subtype. Positions **3** third-party, **4** nominal, **5** export, **6** summary and **7** self-billed are the five flags. **invoicing.md ("3 to 7") is correct; zatca.md §3.4 ("positions 4–7") must change to "positions 3–7".** The XML Standard's own prose (§11.2.1 p.30, "final four positions") and the DD example "010100" (6 characters) contradict the rule. The normative rule wins.
