# ZATCA SDK verification kit (2026-10-16)

Scripts and fake test invoices used to check the ZATCA SDK 2.0.3 offline.
Findings: `../zatca-sdk-findings-2026-10-16.md`.

- `inv/` – fake UBL test documents (dummy VAT numbers); candidates for the AT-13 fixtures.
- `scripts/pyhash.py` – invoice hash with lxml (matched SDK `-generateHash` on all test documents).
- `scripts/pysign.py` – proof that lxml + cryptography produce a signed simplified invoice the SDK validates.
- `scripts/fatbc.sh` – runs the SDK offline with BouncyCastle first (needed on Java 17+ for secp256k1).

The SDK itself (LGPL-3) is not stored here; download it from ZATCA's DownloadSDK page.
Paths inside the scripts point to the build session's scratch area; adjust before reuse.

## SDK R3.4.8 / R4.0.0 re-run (2026-10-17)

Findings: `../zatca-sdk-3-findings-2026-10-17.md`. The 2.0.3 scripts above are kept unchanged.

- `inv3/` – new fake documents (generated by `scripts/sdk3/make_invoices3.py`): 386 standard/simplified, final 388
  deducting a 386, KWD with 2- and 3-decimal amounts, seller names of 127/128/200 UTF-8 bytes.
- `scripts/sdk3/fat348.sh` – runs the R3.4.8 jar offline (`unshare -n`). Needs `SDK3_WORK` = a work dir holding a
  **copy** of the SDK as `r348/` (with `r348/Configuration/config.json` in absolute paths; the rules folder is
  `Data/Rules/Schematrons`) and `out/`. Default JCA order SUN first, BouncyCastle second (`bc-second.security`):
  SUN's issuer-name form and BC's secp256k1. `SDK_CONFIG` may point to a config using other rules (e.g. R4.0.0's XSLs).
- `scripts/sdk3/validate_all.sh`, `validate_ownpih.sh` (each file checked against its own PIH), `sign_all.sh`,
  `summarise.py` – batch validate/sign and one-line summaries with rule ids.
- `scripts/sdk3/analyse3.py` – checks hash, SignatureValue, CertDigest, SignedProperties digest, issuer name,
  SigningTime and every QR tag (BER lengths) of a signed document.
- `scripts/sdk3/qr_variants.py` – QR variants of an SDK-signed document (tag 4, tag 3 `Z`, missing tags, 2.0.3 layout,
  1-byte vs BER length).
- `scripts/sdk3/xsl_rules.py` – extracts and diffs the executed schematron assertions of two rule files.
- `scripts/sdk3/sdk3_export_generator.py` – scratch generator of module-signed documents; copy it as `zatca/test_sdk3_export.py` into a
  `git archive HEAD` export only (never into the repo's `zatca/`), set `ZATCA_SDK_DIR` and `SDK3_OUT`.

R4.0.0 jar run (2026-10-18; findings §7 of the same file):

- `scripts/sdk3/fat400.sh` – runs the R4.0.0 jar offline (`unshare -n`). Needs `SDK4_WORK` = a work dir holding a
  **copy** of the SDK as `r400/` (with `r400/Configuration/config.json` in absolute paths; rules folder
  `Data/Rules/schematrons`) and `out/`. Default `PROVIDERS=jdk` (the JDK's own order: R4.0.0 registers BouncyCastle
  itself); `sunbc` / `bc` as for `fat348.sh`. The jar is Java 21 bytecode (class version 65): Java 21 or later.
- `sign_all.sh`, `validate_all.sh`, `validate_ownpih.sh` take `FAT=…/fat400.sh` to use R4.0.0 (default `fat348.sh`);
  for `validate_ownpih.sh` also set `BASE_CONFIG` to the R4.0.0 config.
- `scripts/sdk3/qr_variants4.py` – QR tag 3 / tag 5 variants of a signed simplified document, each with a broken-tag-7
  twin (`+bad7`) so the SDK prints the QR warnings it otherwise hides.
- `scripts/sdk3/variants4.py` – fake B2G (KSA-40 `GOV`, BT-7), 9-position KSA-2 and price-level allowance/charge
  variants of `inv/std-388.xml`.
